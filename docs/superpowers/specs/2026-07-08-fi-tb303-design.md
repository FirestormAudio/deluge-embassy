# Fi-2: TB-303 diode-ladder filter — design & spec

The second sub-project of the **Fi (Filter) suite**: a faithful scalar `no_std` port of the
circuit-accurate **TB-303 diode-ladder VA filter** — the flagship acid-bass sound. Ported
from the first-party `spark` `tb303_diode_va` (Tim Stinchcombe's TB-303 analysis + a
Vult-derived Heun/RK2 diode-ladder solver), de-SIMD'd to plain `f32` and wrapped in our
block/`In` kernel model, validated with the Fi-1 filter QA harness plus aliasing gates.

> **Status:** design proposal. Depends on the merged Fi-1 SVF (the `deluge-dsp-test`
> filter harness: `magnitude_db`, `self_osc_hz_and_rms`; and `spectrum::worst_alias_db`),
> the P0 graph, and P1 Wren bindings. Source of the algorithm is the first-party (owned)
> `spark` filter — no licensing constraint; the port must be numerically faithful, proven
> by behavioral/spectral gates (§4), not a bit-exact golden.

**Fi roadmap (context):** Fi-1 SVF ✅ → **Fi-2 TB-303** (this spec) → Fi-3 Huovilainen
Moog → Fi-4 MS-20 Sallen-Key → Fi-5 modal resonator.

---

## 1. Goals & non-goals

**Goals**
- **Faithful scalar `Tb303` kernel.** Port `spark`'s `tb303_diode_va` structure exactly:
  `input − feedback → 1-stage diode ladder @ 2×cutoff → 3-stage diode ladder @ cutoff →
  [tap] → 6 chained fixed-frequency one-pole high-passes → output`, with a resonance
  feedback path (previous-sample tap of the 3-stage output, scaled, through a fixed 150 Hz
  one-pole HP, subtracted from the input). Nonlinear diode ladder solved with a **Heun/RK2**
  predictor-corrector at **4× oversampling**.
- **Self-oscillating acid character.** At high resonance the feedback loop rings/self-
  oscillates near cutoff — the classic 303 squelch — while staying bounded.
- **Block/`In` API.** `process(input, cutoff, res, dt, out)`; audio-rate cutoff and
  resonance (envelope-swept cutoff is the whole point of the 303).
- **Device-honest structure.** Cache the fixed coefficients; keep the (unavoidable)
  oversampled nonlinear loop as the only heavy per-sample cost.
- **QA-proven** by the Fi-1 harness + aliasing measurement: alias floor across a resonant
  sweep, beats-naive (vs 1× oversampling), self-oscillation, resonant-peak tracking, and
  boundedness. No bit-exact golden — faithfulness is proven behaviorally (as `spark`'s own
  tests are).

**Non-goals (deferred / out of scope)**
- **Drive / accent / envelope circuit.** The 303's accent and internal envelope are a
  patching/voice concern (modulate `cutoff`/`res` from an `Env`), not the filter kernel.
- **Cross-voice SIMD** — the voice/`Sy`-layer axis, uniform across all filters (filters are
  serial recurrences; no across-sample SIMD).
- **Measure-down oversampling** — done. Shipped at a static `const TB303_OVERSAMPLE = 2`,
  chosen by a completed characterization: indistinguishable from an OS=16 reference across
  the normal control range, and self-osc/stability/aliasing are OS=1-identical; the acid-zone
  bifurcation is chaotic and isn't helped by more OS. `TB303_OVERSAMPLE` is the single
  compile-time config point — no runtime field.
- **Const-cutoff fast path** — unlike the SVF, the ladder `g` is transcendental-free and
  cheap, and the oversampled loop dominates, so there's nothing worth hoisting.
- Replacing `OnePole`/`Svf` — `Tb303` is purely additive.

## 2. Kernel DSP (`deluge-dsp-kernels/src/filter.rs`, new `Tb303`)

Port the algorithm from `spark` `libs/dsp/spark/src/processors/filters/{tb303_diode_va.rs,
diode_ladder.rs, iir/one_pole.rs}`. The math is already scalar-shaped (`Simd<f32,1>` /
`f32x1`), so this is a **mechanical de-SIMD** — replace 1-lane SIMD ops with the identical
`f32` ops — not an algorithmic redesign. Read those files as the authoritative algorithm.

```rust
pub struct Tb303 {
    // 1-stage + 3-stage diode-ladder integrator states (4 f32), the 6 fixed
    // one-pole HP states + their cached coefficients, the 150 Hz res-HP state +
    // cached coefficient, the previous-sample feedback tap, cutoff/res, and the
    // oversampling factor. All fixed-size; no heap.
    // (exact fields follow the spark struct, de-SIMD'd.)
}

impl Tb303 {
    pub fn new() -> Tb303;                 // oversampling = 4 (TB303_OVERSAMPLE)
    pub fn with_oversample(os: u32) -> Tb303; // test/tuning hook (beats-naive gate)
    pub fn process(&mut self, input: In, cutoff: In, res: In, dt: f32, out: &mut [f32]);
}
```

**Per-sample (`process`, over the block):**
1. Resolve `cutoff = cutoff.at(i).clamp(20.0, 2000.0)` and `res = res.at(i).clamp(0.0, 1.0)`.
2. Update the two ladders' `g` from `cutoff` (stage1 at `2·cutoff`, stage234 at `cutoff`):
   `fh = 2π·cutoff/(OS·fs)` → ladder coefficient. **No transcendental** — cheap per sample.
   `res_gain = res · 2.0`.
3. Feedback: `x = input.at(i) − res_highpass(res_tap · res_gain)` (the 150 Hz HP and its
   coefficient are **fixed, cached at construction**).
4. `y1 = ladder1.process(x)` (1 stage @ 2×cutoff), `y = ladder234.process(y1)` (3 stages
   @ cutoff); `res_tap = y` (tap for next sample's feedback).
5. `out[i] = hp_chain(y)` — the 6 fixed one-pole HPs in series (coefficients cached at
   construction from the fixed corner table `[97.5, 38.5, 4.45, 578.1, 20.0, 7.41]` Hz).

**Diode ladder (`ladderN.process`)** runs `OS` (=4) Heun/RK2 sub-steps per sample; each
sub-step evaluates the stage saturation per stage. Total ~64 saturation evals/output-sample
(16 for the 1-stage @ 4×, 48 for the 3-stage @ 4×) — the dominant cost, inherent to the model
(the A9's VFPv3 has a hardware `VDIV.F32`, so the rational below is affordable at this rate).

**Nonlinearity — a principled upgrade over spark's cubic (deliberate deviation).** spark's
diode ladder uses `clamp(x − x³/3, ±2/3)` — but `x − x³/3` is just the **3rd-order Taylor
series of `tanh`**, and the real diode I-V curve *is* `tanh`-like. The cubic is only accurate
to `|x|≲1` and then goes **non-monotonic and sign-flips** (a polynomial artifact, not diode
behavior). This port instead uses a **Padé [3/2] `tanh` approximation** (from `skylib`'s
`SoftLimit`):

```
diode_sat(x) = clamp( x·(27 + x²) / (27 + 9·x²), −1.0, 1.0 )
```

Monotonic everywhere (derivative `9(x²−9)²/denom² ≥ 0`), accurate to `tanh` out to `|x|≈3`,
and it reaches ±1 *tangentially* at `x=±3` (zero slope there) so the ±1 clamp is C¹-smooth.
Small-signal it is identical to the cubic (unit slope at 0), so the ladder's **linear response
— cutoff, frequency shape — is unchanged**; only the large-signal saturation differs, making
it closer to the real diode. This makes Fi-2 a **"303-accurate diode ladder"** (faithful to
spark's topology, oversampling, chain, and feedback structure) rather than a byte-faithful
copy of spark's cubic. The same `SoftLimit` `tanh` is reused by Fi-3 (Huovilainen Moog). The
saturation change may shift the self-oscillation onset — **re-validated and, if needed, the
outer feedback gain re-tuned, by the §4 spectral gates** (self-osc + boundedness).

**Coefficient caching (improvement over spark).** `spark` recomputes the 6 HP + res-HP
`.tan()` coefficients on every `set_cutoff`, even though those corners are fixed constants.
The port computes them **once in `new()`** and never again; only the two ladder `g` values
(transcendental-free) update per sample. This removes the per-sample `.tan()` perf trap.

**`no_std`:** `libm` only if a construction-time `.tan()` is used for the fixed HP
coefficients (once per filter — negligible); the hot loop is pure `f32` arithmetic.
Deterministic; state is fixed-size. No SIMD.

## 3. Graph & Wren surface

**`deluge-audio-graph`:**
- Add `Kind::Tb303`. `Node::new` maps it to `State::Tb303(Tb303::new())`. Render arm:
  `if let State::Tb303(f) = &mut self.state { f.process(ins[0], ins[1], ins[2], dt,
  outs.port(0)); }` — port 0 = input, 1 = cutoff, 2 = resonance. `out_width` = 1.

**`deluge-wren-core`:**
- A `Tb303` Wren class with one factory (the 303 is lowpass-only):
  `Tb303.lp(input, cutoff, res)` → `NewNode { kind: Kind::Tb303, args: [input, cutoff, res] }`
  (a `node_tb303_impl` mirroring `node_svf_impl` but without a response code). Plus the
  shared `cutoff=`/`res=` instance setters (ports 1/2) already added for `Svf` — reused, no
  new setter code.
- Registration in both binding tables (`wren-sys` `static_method`, `SlotApi` `method`),
  and the `class Tb303` sugar in `prelude.wren`.

## 4. QA acceptance & testing

Reuse the Fi-1 filter harness (`deluge_dsp_test::filter_meas::{magnitude_db,
self_osc_hz_and_rms}`) and `spectrum::{analyze, worst_alias_db, level_at}`.

**`deluge-dsp-kernels` tests:**
- **Aliasing floor (the payoff).** Render a resonant patch (e.g. 55/110 Hz saw-ish input
  or self-oscillation, high `res`, cutoff swept over the 303 range), FFT, assert
  `worst_alias_db` below a **measured** floor across the sweep. The 4× oversampling is what
  buys this.
- **Beats naive.** The same render at `with_oversample(1)` aliases badly; assert the 4×
  version is better by **> N dB** (N measured). A wrong port (broken Heun step, wrong
  feedback sign) makes 4× no better than 1× — this catches it.
- **Self-oscillation.** At `res = 1` with a brief excitation and no sustained input, the
  filter sustains a tone near `cutoff` (via `self_osc_hz_and_rms`) that neither decays to
  silence nor grows unbounded — proves the resonance feedback loop is tuned right.
- **Resonant peak tracks cutoff.** For several cutoffs, the spectral peak of a
  high-resonance render sits near `cutoff` and moves monotonically with it.
- **Resonance boosts the peak.** Peak gain at high `res` exceeds low `res` (monotonic).
- **Boundedness (P0 gate).** Proptest: `cutoff ∈ [20, 2000]`, `res ∈ [0, 1]`, bounded
  input → every output sample finite and within a measured bound (the `tanh` saturation bounds
  the ladder; the resonance loop can ring, so the bound is > ±1 — set from measurement).
- **Cutoff/res clamping.** Out-of-range `cutoff` (e.g. 5 Hz, 8 kHz) and `res` (e.g. −1, 2)
  clamp rather than destabilizing — finite, bounded output (mirrors the SVF's
  `const_cutoff_above_nyquist` regression lesson).

**Graph/Wren:** a `Kind::Tb303` node renders bounded/non-silent; `Tb303.lp(in,c,r)` emits
the right `Cmd` and renders finite/non-silent; `cutoff=`/`res=` update the running node.

**Determinism:** no RNG in the kernel; reproducible host/device. Proptests seed-fixed.
**Faithfulness** is established by these behavioral/spectral gates (as in `spark`'s own
test suite), not a bit-exact reference golden.

## 5. Deferred / follow-ups

- **Measure-down oversampling** (4× → 2×) after on-device alias/CPU measurement.
- **Drive / accent / internal envelope** — the 303's accent circuit, as a voice-layer or
  a follow-on filter feature.
- **Cross-voice SIMD** at the `Sy` voice layer.
- A direct **spark-reference golden** (capture + tolerance-compare) if a stronger
  faithfulness proof is ever wanted.
- Fi-3 Huovilainen Moog, Fi-4 MS-20, Fi-5 modal resonator — separate specs, reusing this
  suite's harness + aliasing gates.
