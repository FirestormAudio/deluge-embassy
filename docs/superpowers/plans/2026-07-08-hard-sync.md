# Hard sync oscillator Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans. Steps use checkbox (`- [ ]`) syntax.

**Goal:** A single-node hard-sync oscillator (`SyncOsc`): an internal master resets the slave each cycle, with a BLEP-anti-aliased reset — the classic sync-sweep sound. Four sync kinds + `Osc.syncX(master, slave)` Wren surface. `Osc` stays bit-exact via a shared waveshape helper.

**Architecture:** Extract `Osc`'s per-sample waveshaping into `wave_sample(wave, ph, dtp, width)` (both `Osc` and `SyncOsc` use it). `SyncOsc { master_phase, slave_phase }` advances the master, resets the slave on master wrap, and adds a reset BLEP scaled by the naïve step. New graph kinds `SyncSine/SyncSaw/SyncSquare/SyncTri` → `State::Sync(SyncOsc)`; Wren `Node.sync_(waveCode, master, slave)`.

**Tech Stack:** Rust `no_std` (`deluge-dsp-kernels`), `deluge-audio-graph`, `deluge-wren-core`; QA via `deluge-dsp-test` (`worst_alias_db`). Host target `x86_64-unknown-linux-gnu`.

**Reference spec:** [hard sync](../specs/2026-07-08-hard-sync-design.md).

## Global Constraints

- **`Osc::process` bit-exact** after extracting `wave_sample` — all Osc-1/Osc-2 oscillator tests + goldens (`golden_saw_lpf_env_first_block`, `golden_saw_lpf_renders_expected_block`) unchanged.
- **Reset-BLEP correctness is measured:** the sync alias floor and the beats-naïve margin are set from measurement (Osc-1 discipline). A wrong reset-BLEP sign makes aliasing WORSE than naïve — the beats-naïve test is the correctness anchor.
- `no_std`; deterministic (no RNG); `poly_blep` reused (no new anti-aliasing math beyond the reset step). Zero warnings.
- Ports: 0 = master freq (pitch), 1 = slave freq (timbre). No `MAX_INPUTS` change.
- Test commands: `-p deluge-dsp-kernels`, `-p deluge-audio-graph` (+`--features simd`), `-p deluge-wren-core --features test-support`; firmware compile (device target, both audio modes).

## Reference values

- `osc.rs` (post Osc-2): `Osc { phase, last, last2, feedback }`, `process(&mut self, wave: Wave, freq: In, pmod: In, width: In, dt: f32, out: &mut [f32])` — per sample computes `dtp=freq.at(i)*dt`, `fb`, `ph=frac(phase+pmod.at(i)+fb)`, then a `match wave { Sine=>fast_sin(ph), Saw=>(2*ph-1)-poly_blep(ph,dtp), Square=>{width→w, naive±1 + poly_blep(ph,dtp) - poly_blep(frac(ph-w),dtp)}, Tri=>{naive + 8*dtp*(poly_blamp(ph,dtp)-poly_blamp(frac(ph+0.5),dtp))} }`, `*s=y`, updates last/last2, advances phase. `poly_blep(t,dtp)`, `poly_blamp`, `fast_sin`, `floorf`, `Wave{Sine,Saw,Square,Tri}` all exist.
- `node.rs`: `enum Kind { Sine, Saw, Square, Tri, Noise, PinkNoise, BrownNoise, Env, Lpf, Mul, Add, Sub, Split2 }`; `Node::new` maps `Kind::Sine|Saw|Square|Tri => State::Osc(Osc::new())`; render arm maps those kinds → `Wave` and calls `o.process(wave, ins[0], ins[1], ins[2], dt, outs.port(0))`. `enum State { Osc, Noise, Ar, OnePole, Stateless }`.
- Wren: `node_src_impl` + `src_kind(code)` (0=Sine,1=Saw,2=Square,3=Tri) → `Node.src_(code, freq)`; `Osc.sine/saw/square/tri` sugar. 4-place registration.

- [ ] **Step 4: Implement `SyncOsc`**

```rust
#[derive(Clone, Copy, Default)]
pub struct SyncOsc { master_phase: f32, slave_phase: f32 }

impl SyncOsc {
    pub fn new() -> SyncOsc { SyncOsc::default() }

    pub fn process(&mut self, wave: Wave, master_freq: In, slave_freq: In, dt: f32, out: &mut [f32]) {
        for (i, s) in out.iter_mut().enumerate() {
            let dtp_m = master_freq.at(i) * dt;
            let dtp_s = slave_freq.at(i) * dt;

            // Band-limited slave value at its current phase (natural-wrap BLEP included).
            let mut y = wave_sample(wave, self.slave_phase, dtp_s, 0.5);

            // Advance master; detect a wrap → hard-reset the slave with a BLEP.
            let mp = self.master_phase + dtp_m;
            if mp >= 1.0 && dtp_m > 0.0 {
                let t_reset = (1.0 - self.master_phase) / dtp_m; // sub-sample position in [0,1)
                // slave phase at the reset instant, and the naïve step across the reset:
                let ph_at_reset = { let mut p = self.slave_phase + t_reset * dtp_s; p -= floorf(p); p };
                let step = naive_wave(wave, 0.0) - naive_wave(wave, ph_at_reset);
                // poly_blep residual at the reset's fractional position, scaled by the step.
                // (sign/scale validated by the alias-floor + beats-naive tests — Step 5.)
                y += step * poly_blep(t_reset, dtp_s.max(dtp_m));
                self.master_phase = mp - 1.0;
                // Slave restarts from 0, advanced by the remaining fraction of the sample.
                self.slave_phase = (1.0 - t_reset) * dtp_s;
                self.slave_phase -= floorf(self.slave_phase);
            } else {
                self.master_phase = mp - floorf(mp);
                self.slave_phase += dtp_s;
                self.slave_phase -= floorf(self.slave_phase);
            }
            *s = y;
        }
    }
}
```
> The reset-BLEP `poly_blep(t_reset, ...)` width and the `step * ±` sign are the one
> subtle part — Step 5 validates them by measurement (the beats-naïve test flips wrong
> signs into WORSE-than-naïve). Adjust the `poly_blep` argument form / sign until the
> alias floor is minimized; do NOT loosen the gate to accept a bad correction.
